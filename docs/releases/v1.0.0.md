# Entrega v1.0.0

Data: 13/10/2026. O usuário autorizou concluir as etapas restantes e publicar sem confirmações entre versões.

## Objetivo e escopo

Entregar o MVP gratuito e utilizável online: fontes públicas, datas/elegibilidade transparentes, PDF privado com revisão, ranking por evidências, pesos, filtros e atualização periódica. Sem candidaturas automáticas, chaves públicas, currículo publicado ou chamadas pagas.

## Arquivos e decisões

- `apps/web/src/services/public-api.ts`: adaptador em memória para perfil/score, com validação Zod e o mesmo motor puro do backend.
- `api.ts`: seleciona API local ou adaptador público. O único fetch público de dados é GET do jobs.json; perfil e PDF não entram nesse pedido.
- `browser-pdf.ts`: extração PDF.js em worker local, lazy loading, limites de tamanho/páginas/texto/tempo e destruição após processamento.
- `public-api.test.ts`: revisão obrigatória, isolamento entre sessões, ausência de envio do perfil ao loader, recência reavaliada, IA desativada e cancelamento.
- `scripts/export-public-jobs.mjs`: coleta somente dados de vagas, sem importar repositório de currículos.
- `.github/workflows/pages.yml`: valida, coleta, preserva cache/cooldown e publica somente o frontend, em main e a cada seis horas.
- `apps/web/public/jobs.json`: estado inicial vazio e explicitamente ainda não consultado; o Actions substitui no artefato, sem commitar anúncios.

Alterados: componentes e App para usar adaptador, mensagens específicas de privacidade/atualização pública, Vite base configurável, configuração de HOST da API limitada a loopback, teste do host, versões/lockfile, README/CHANGELOG/roadmap/arquitetura e .gitignore do cache público.

O público usa memória por aba: recarregar descarta o perfil, evitando dados privados persistidos em computador compartilhado. A API pessoal permanece local e preserva perfil revisado em JSON. PostgreSQL e autenticação ficam para uma futura API multiusuário; não são necessários para um site estático que não recebe currículos. IA opcional continua local, explicitamente desligada por padrão. PDF.js já era dependência transitiva e foi declarado diretamente para importação no frontend.

## Aceite e validação

- 81 testes: 69 API e 12 frontend, incluindo privacidade e host.
- Lint, TypeScript strict e build público aprovados.
- Audit de dependências de produção: zero vulnerabilidades.
- Deploy publica somente arquivos estáticos e jobs públicos; não inclui private, .env ou PDF.
- Fontes podem retornar zero vagas elegíveis/recentes; não usamos fixtures como anúncios reais.
- Navegador e publicação: conferir fluxo de PDF sintético e página ao concluir deploy; resultado registrado no relatório final.

## Como testar

Online: abrir o endereço do README, selecionar PDF com texto, extrair, revisar e salvar. Calcular compatibilidade, ajustar filtros e abrir fonte original. Recarregar deve descartar o perfil público. Datas incertas continuam em grupo separado. No modo local, npm run dev preserva o perfil revisado em arquivo privado.

Git: `feat: publish private browser matching MVP`. Publicar develop, aguardar CI, integrar main por fast-forward e publicar tag v1.0.0. Ajustes necessários após teste de deploy recebem commits fix/docs próprios; não reescrever histórico publicado.

## Limites operacionais

MVP não garante cobertura de todas as vagas, equivalência semântica completa, data conhecida ou disponibilidade do anúncio. Score mede critérios identificados, não chance de contratação. PDF digitalizado precisa de OCR externo, fora do MVP. Sem login/persistência pública/IA no navegador. Actions pode atrasar ou pausar agendas inativas; cache não é banco distribuído. API local é de usuário único e uma instância. Evoluções: perfis autenticados, armazenamento transacional, fontes adicionais autorizadas e observabilidade compartilhada.
